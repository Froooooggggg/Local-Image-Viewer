# 图集查看器接入「同传互译」本机翻译服务

> 客户端实施稿 · 对应翻译端 `0.8.0-beta`（versionCode 8）
> 服务端技术文档：`docs/翻译互通-技术文档.md`（架构/取舍）
> 本文只讲**图集端怎么接**，按当前代码实测字段写，可直接交给实现会话。

---

## 0. 一页纸结论

图集 App 通过 **本机 HTTP** 调用翻译 App：

```
GET  http://127.0.0.1:{port}/v1/health                  # 不需要 token
POST http://127.0.0.1:{port}/v1/translate/text          # 单条文本
POST http://127.0.0.1:{port}/v1/translate/image?...     # 整页图片
GET  http://127.0.0.1:{port}/v1/render/{id}             # 取成品图
```

- 端口从 `/v1/health` 的 `port` 字段读，**不要写死**；默认 8098，被占则 8099/8100。
- 除 `/v1/health` 外都要 `X-Bridge-Token`。
- 图片请求体就是原始图片字节，不 base64、不 multipart。
- 服务端**串行**处理 OCR/翻译；同一时刻只允许一个图片请求，第二个返回 `409 busy`。
- 图集端只读原图，输出写到用户选择的 SAF 目录；不申请存储权限，不改原 zip/文件夹。
- 处理完把输出子目录用现有 `importSingleFolder` 导入图集。

当前服务端实测（2026-10-31，Redmi K80 Pro / 天玑 8300 / HTP0）：

| 接口 | 结果 |
|---|---|
| health | 正常 |
| text（日→中，11 字） | 292 ms |
| image（900×1200，8 个文本块） | OCR 876 ms + 翻译 1.7 s + 出图 63 ms，总 2.3 s |
| image（1440×218，1 个文本块） | 555 ms |

> 漫画页会比截图慢；按 **3–10 秒/页** 估工期。几百页必须做断点续跑。

## 1. 职责边界（先明确，避免又做成两套模型）

| 事项 | 图集 App | 翻译 App |
|---|---|---|
| 读取原图 / zip | ✅ | ❌ |
| OCR | ❌ | ✅ |
| 翻译 | ❌ | ✅ |
| 把译文嵌回图片 | ❌（直接保存服务端成品图） | ✅ |
| 选择输出目录 / 写结果 | ✅ | ❌ |
| 导入结果到图集列表 | ✅ | ❌ |
| 申请存储权限 | ❌（只用 SAF） | ❌ |
| 上传图片/译文 | ❌ | ❌（只监听 127.0.0.1） |

图集端**不要**在本地再跑 OCR/翻译；服务端返回的 `render` 就是成品图，客户端只负责下载、落盘、导入。

## 2. 连接前准备

### 2.1 Android 清单

图集 App 的 `android/app/src/main/AndroidManifest.xml` 必须加：

```xml
<uses-permission android:name="android.permission.INTERNET" />

<application
    android:usesCleartextTraffic="true"
    ... >
```

- `INTERNET`：localhost HTTP 也需要。
- `usesCleartextTraffic="true"`：targetSdk 36 默认禁止明文 HTTP；只对本机回环开放，风险可接受。更严格可改用 `network_security_config` 只放行 `127.0.0.1`。
- 不需要 `READ/WRITE_EXTERNAL_STORAGE`。

### 2.2 检查翻译端是否在跑

```http
GET http://127.0.0.1:8098/v1/health
```

成功响应（实际字段）：

```json
{
  "api": 1,
  "ok": true,
  "app": "同传互译",
  "version": "0.8.0-beta",
  "backend": "llama",
  "model": "Huihui-Qwen3.5-2B-abliterated.Q4_K_M.gguf",
  "visionReady": true,
  "translateReady": true,
  "bridgeEnabled": true,
  "port": 8098
}
```

判断顺序：

1. `ok == true && api == 1`
2. `translateReady == true`（false 时 `error` 字段会说明模型缺失/后端未配置）
3. `visionReady == true`（false 时同样看 `error`）
4. `port` 作为后续 base URL 的端口；**不要用请求时猜的端口**

失败处理：

| 现象 | 提示 |
|---|---|
| `ECONNREFUSED` / timeout | “同传互译未运行，或未开启图集互联” |
| `bridgeEnabled=false` | “请在 同传互译 → 全局翻译设置 → 图集互联 打开开关” |
| `translateReady=false` | “请在 同传互译 里选择可用的翻译模型” |
| 401 | “配对码不对，请在 同传互译 → 图集互联 → 配对 里重新复制” |

> ⚠️ **实现核对（0.8.0-beta，2026-10-31）**：`PairActivity` 在 AndroidManifest 里是 `android:exported="false"`，图集端**不能**用 `Intent.setClassName` 直接拉起，否则会抛 `SecurityException`。不要照早期设计的跨应用 Intent 做配对。
>
> 当前可用流程（剪贴板配对）：
>
> 1. 用户在翻译 App 打开 **全局翻译设置 → 图集互联 → 配对**。
> 2. 配对页打开后会主动把一段 JSON 复制到剪贴板，也可点“复制”：
>    ```json
>    {"api":1,"port":8098,"token":"<48 位 hex>","hosts":["127.0.0.1","192.168.1.20"]}
>    ```
> 3. 图集端点“从剪贴板粘贴”，解析 JSON，取 `token` 和 `port`。
> 4. `token` 是 48 位小写 hex；不要写死长度，`trim()` 后校验非空即可，严格时可校验 `^[0-9a-f]{48}$`。
>
> 图集端只显示“打开同传互译 → 图集互联 → 配对”的文字指引；不要尝试拉起未导出的 Activity。

### 2.3 token

- 首次：用户在翻译 App 的 **图集互联 → 配对** 页打开配对页；页面会自动把 `{api,port,token,hosts}` 复制到剪贴板，也可点“复制”。
- 图集端读取剪贴板文本 → `jsonDecode` → 取 `token`、`port`；不要假设 token 长度，但当前实现是 **48 位小写 hex**。
- 图集存 `SharedPreferences`（`bridge_token`、`bridge_port`），不要写日志。
- token 只在请求头：

```http
X-Bridge-Token: 48 位 hex
```

- token 重新生成后旧值立刻 401；图集要允许用户重新配对。
- 图集端**不要**尝试从翻译 App 的私有目录读 token。
- 图集端**不要**用 `Intent` 拉起 `PairActivity`：该 Activity 未导出，外部拉起会 `SecurityException`。

Dart 侧读取剪贴板：

```dart
import 'package:flutter/services.dart';
import 'dart:convert';

Future<({String token, int port})?> pastePairing() async {
  final data = await Clipboard.getData(Clipboard.kTextPlain);
  final raw = data?.text?.trim();
  if (raw == null || raw.isEmpty) return null;
  final json = jsonDecode(raw) as Map<String, dynamic>;
  final token = (json['token'] as String?)?.trim();
  final port = (json['port'] as num?)?.toInt();
  if (token == null || token.isEmpty || port == null) return null;
  return (token: token, port: port);
}
```

### 2.4 用 Flutter 自带 `HttpClient`，不要额外加依赖

图集项目当前没有 `http` 包；用 `dart:io` 即可。

```dart
import 'dart:convert';
import 'dart:io';
import 'dart:typed_data';

class BridgeClient {
  BridgeClient({required this.port, required this.token});

  final int port;
  final String token;
  final HttpClient _http = HttpClient()
    ..connectionTimeout = const Duration(seconds: 3)
    ..idleTimeout = const Duration(seconds: 30);

  Uri _uri(String path, [Map<String, String>? query]) =>
      Uri(scheme: 'http', host: '127.0.0.1', port: port, path: path, queryParameters: query);

  Future<Map<String, dynamic>> health() async {
    final req = await _http.getUrl(_uri('/v1/health'));
    req.headers.set(HttpHeaders.acceptHeader, 'application/json');
    final resp = await req.close().timeout(const Duration(seconds: 3));
    final body = await _readAll(resp);
    final json = jsonDecode(utf8.decode(body)) as Map<String, dynamic>;
    if (resp.statusCode != 200 || json['ok'] != true) {
      throw BridgeException(resp.statusCode, json['code'] as String? ?? 'health_failed',
          json['message'] as String? ?? json['error'] as String? ?? 'health failed');
    }
    return json;
  }

  Future<Map<String, dynamic>> translateText({
    required String text,
    String source = 'auto',
    String target = 'zh',
  }) async {
    final req = await _http.postUrl(_uri('/v1/translate/text'));
    req.headers.set('X-Bridge-Token', token);
    req.headers.contentType = ContentType.json;
    req.add(utf8.encode(jsonEncode({'text': text, 'source': source, 'target': target})));
    final resp = await req.close().timeout(const Duration(seconds: 30));
    final body = await _readAll(resp);
    final json = jsonDecode(utf8.decode(body)) as Map<String, dynamic>;
    if (resp.statusCode != 200 || json['ok'] != true) {
      throw BridgeException(resp.statusCode, json['code'] as String? ?? 'text_failed',
          json['message'] as String? ?? 'text failed');
    }
    return json;
  }

  Future<Map<String, dynamic>> translateImage(
    Uint8List bytes, {
    String source = 'auto',
    String target = 'zh',
    bool render = true,
    int maxSide = 4096,
    int minChars = 0,
  }) async {
    final uri = _uri('/v1/translate/image', {
      'source': source,
      'target': target,
      'ocr': '1',
      'translate': '1',
      'render': render ? '1' : '0',
      'maxSide': '$maxSide',
      'minChars': '$minChars',
    });
    final req = await _http.postUrl(uri);
    req.headers.set('X-Bridge-Token', token);
    req.headers.contentType = ContentType('image', 'jpeg'); // 服务端不校验，jpeg/png 均可
    req.contentLength = bytes.length;
    req.add(bytes);
    final resp = await req.close().timeout(const Duration(seconds: 120));
    final body = await _readAll(resp);
    final json = jsonDecode(utf8.decode(body)) as Map<String, dynamic>;
    if (resp.statusCode != 200 || json['ok'] != true) {
      throw BridgeException(resp.statusCode, json['code'] as String? ?? 'image_failed',
          json['message'] as String? ?? 'image failed');
    }
    return json;
  }

  Future<Uint8List> fetchRender(String path) async {
    final req = await _http.getUrl(_uri(path));
    req.headers.set('X-Bridge-Token', token);
    final resp = await req.close().timeout(const Duration(seconds: 30));
    final body = await _readAll(resp);
    if (resp.statusCode != 200) {
      final text = utf8.decode(body, allowMalformed: true);
      throw BridgeException(resp.statusCode, 'render_failed', text);
    }
    return body;
  }

  static Future<Uint8List> _readAll(HttpClientResponse resp) async {
    final builder = BytesBuilder(copy: false);
    await for (final chunk in resp) {
      builder.add(chunk);
    }
    return builder.takeBytes();
  }

  void close() => _http.close(force: true);
}

class BridgeException implements Exception {
  BridgeException(this.status, this.code, this.message);
  final int status;
  final String code;
  final String message;
  @override
  String toString() => 'BridgeException($status, $code): $message';
}
```

超时建议：

| 请求 | 超时 |
|---|---|
| health | 3 s |
| text | 30 s |
| image（单页） | 120 s |
| render 下载 | 30 s |

## 3. HTTP 契约（按当前实现）

### 3.1 `POST /v1/translate/text`

请求：

```json
{"text":"もう少しゆっくり話してもらえますか。","source":"ja","target":"zh"}
```

- `source`/`target` 取 `auto|ja|en|ko|zh`；`auto` 按文本猜。
- `Content-Type: application/json; charset=utf-8`。

响应：

```json
{
  "api": 1,
  "ok": true,
  "text": "能请您再说慢一点吗？",
  "sourceLang": "ja",
  "targetLang": "zh",
  "elapsedMs": 292,
  "backend": "llama"
}
```

### 3.2 `POST /v1/translate/image`

Query 参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `source` | `auto` | **日语漫画请显式传 `ja`**；`auto` 会按每块文本猜语言，纯汉字台词可能被猜成中文而跳过翻译 |
| `target` | `zh` | `zh/en/ja/ko` |
| `ocr` | `1` | 0 时跳过 OCR，返回空 lines（调试用） |
| `translate` | `1` | 0 时只 OCR，不翻译 |
| `render` | `1` | 1 时返回成品图 id |
| `maxSide` | `4096` | 解码最长边上限；超过原图则保持原图 |
| `minChars` | `0` | 小于该字符数的块丢弃；漫画建议 1 |

请求体：原始图片字节（JPEG/PNG/WebP…），`Content-Type` 用 `image/jpeg` 或 `application/octet-stream` 均可。

限制：

- 请求体 ≤ **32 MiB**
- 原图单边 ≤ **4096 px**、总像素 ≤ **6400 万**
- 超限返回 `413`

响应：

```json
{
  "api": 1,
  "ok": true,
  "image": {"width": 900, "height": 1200},
  "lines": [
    {
      "i": 0,
      "source": "おはよう！今日もいい天気だね。",
      "target": "早上好！今天天气真好呢。",
      "box": [68, 141, 366, 83],
      "conf": 0.985,
      "ok": true,
      "error": null
    }
  ],
  "stats": {
    "blocks": 8,
    "translated": 8,
    "failed": 0,
    "dropped": 2,
    "ocrMs": 876,
    "translateMs": 1766,
    "renderMs": 63,
    "elapsedMs": 2733
  },
  "render": {
    "id": "231bcd1545db4b1c905dfb8a3355cec7",
    "format": "jpeg",
    "path": "/v1/render/231bcd1545db4b1c905dfb8a3355cec7"
  }
}
```

字段说明：

- `image.width/height`：**已应用 EXIF 旋转、已按 maxSide 缩放后**的尺寸；`lines[].box` 与它同一坐标系。
- `box`：`[left, top, width, height]`，单位像素；不是 `[left, top, right, bottom]`。
- `target` 为空、`ok=false` 表示这块没翻成中文；客户端**不要**用 `source` 覆盖，保留原图/跳过这块。
- `render` 仅在 `render=1` 且渲染成功时出现；失败时字段不存在，外层仍可为 `ok=true`。
- `stats.dropped` 包含被过滤/合并掉的行，**不是**错误数。

### 3.3 `GET /v1/render/{id}`

```http
GET /v1/render/231bcd1545db4b1c905dfb8a3355cec7 HTTP/1.1
X-Bridge-Token: <token>
```

- 返回 `image/jpeg` 字节。
- 缓存：最多 4 张、10 分钟；过期/淘汰返回 `410 render_gone`。
- 客户端拿到 image 响应后应**立即**下载 render，不要等整批结束再下载。
- `410` 时重发该页图片请求一次；仍失败就保存原图并记 `renderMissing`。

### 3.4 错误形状

```json
{"api":1,"ok":false,"code":"busy","message":"另一个 OCR/翻译任务正在运行"}
```

| HTTP | code | 客户端动作 |
|---|---|---|
| 400 | `bad_request` | 修参数，不重试 |
| 401 | `unauthorized` | 重新配对，不重试 |
| 404 | `not_found` | 检查路径 |
| 408 | `timeout` | 网络慢，重试一次 |
| 409 | `busy` | 等 1 s 重试；不要并发 |
| 410 | `render_gone` | 重发该页一次 |
| 413 | `body_too_large` / `image_too_large` | 该页太大；预缩放或跳过并记录 |
| 415 | `unsupported_media_type` / `bad_image` | 换图片格式/内容 |
| 500 | `bridge_error` / `ocr_failed` / `image_decode_failed` | 记该页失败，继续下一页 |
| 503 | 连接拒绝（不是 HTTP 503） | 翻译 App 未运行/开关关闭；提示用户打开 |

重试策略：

- `409`：1 s 后重试，最多 3 次；
- `408`/`5xx`：2 s 后重试一次；
- `401/413/410`：不盲目重试（410 只重发一次图片请求）；
- 连续 3 页失败：暂停批次，提示用户检查翻译 App，不要空跑几百页。

## 4. 批量任务设计

### 4.1 页面从哪来

图集已经有 `GalleryImage`，不要重新解析：

```dart
final images = gallery.images; // 已按图集排序
```

**文件夹图集**：

```dart
final source = GalleryRepository.instance.byteSourceFor(img.path);
try {
  final bytes = await source.read(0, await source.length());
} finally {
  await source.close();
}
```

> 单张可能几百 MB 的扫描图；如果超过 32 MiB，先让原生层降采样/转 JPEG 再发。
> 普通漫画页 1–5 MB，直接发即可。

**zip 图集**：

```dart
final byteSource = GalleryRepository.instance.byteSourceFor(gallery.sourcePath);
final index = await ZipIndex.openSource(byteSource);
try {
  for (final entry in index.imageEntries) {
    final bytes = await entry.read(byteSource);
    // POST bytes
  }
} finally {
  await byteSource.close();
}
```

- 不要用 `archive` 包的 `ZipFile`（会把整包读进内存）。
- `imageEntries` 已过滤图片，顺序按 zip 中央目录；如果图集列表有自己的排序，用 `gallery.images` 的 `entryIndex` 映射回 `ArchiveEntry`。

### 4.2 串行，不要并发

服务端是单通道：

- 同时发第二个图片请求 → `409 busy`；
- 客户端批次固定 `concurrency = 1`；
- 不要用 `Future.wait` 并发跑页；
- 翻译 App 正在同传/识图时也会 409，要让用户先停掉。

### 4.3 输出目录

用户选一个 SAF 树（`OpenDocumentTree`），图集端创建**子目录**，不要直接写根：

```
<用户选的目录>/
  └── 译_<图集名>_20261031_2140/
      ├── manifest.json
      ├── page-0001.jpg
      ├── page-0002.jpg
      └── ...
```

- 子目录名清洗 `/\:*?"<>|`，截断 40 字；
- 已存在同名目录时追加 `_2`，不要覆盖；
- 原 zip/文件夹只读，**绝不写回**。

### 4.4 断点续跑

`manifest.json` 每页成功后原子写（临时文件 + rename）：

```json
{
  "api": 1,
  "source": "content://...",
  "target": "zh",
  "createdAt": "2026-10-31T21:40:00+08:00",
  "pages": [
    {
      "index": 1,
      "sourceName": "001.jpg",
      "output": "page-0001.jpg",
      "width": 1280,
      "height": 2590,
      "lines": 8,
      "translated": 8,
      "failed": 0,
      "elapsedMs": 2338,
      "renderMissing": false,
      "error": null
    }
  ]
}
```

启动批次时：

1. 读 `manifest.json`；
2. 对 `pages[i].output` 已存在且 `error == null` 的页跳过；
3. 其余页重跑；
4. `manifest.pages` 按 index 合并，不丢旧记录。

### 4.5 保存成品图

```dart
final render = json['render'] as Map<String, dynamic>?;
if (render == null) {
  // 服务端没出图：保存原图，manifest 标 renderMissing=true
  await saf.writeBytes(originalUri, bytes);
} else {
  final imageBytes = await client.fetchRender(render['path'] as String);
  await saf.writeBytes(outputUri, imageBytes);
}
```

- 输出扩展名固定 `.jpg`（服务端就是 JPEG）；
- 文件名 `page-%04d.jpg`，保证图集按名称排序正确；
- 不要用原始文件名（可能重名/非法字符）。

### 4.6 完成后自动导入

```dart
final result = await GalleryRepository.instance.importSingleFolder(
  outputDirUri,
  '译_${gallery.title}',
);
```

- `importSingleFolder(String folderUri, String title)` 是现有 API（位置参数）；
- 导入后切到“图集”tab，SnackBar 提示“已翻译 N 页，导入 M 张”；
- 导入失败时不要删输出目录，提示用户手动“导入文件夹”。

## 5. 原生 SAF 写能力（必须新增）

图集现有 `SafChannel` 只有读。批量输出需要加 4 个方法：

```kotlin
// MainActivity.kt / SafChannel.kt
"createDirectory" -> { parentUri, name -> ... }
"createFile"      -> { parentUri, mime, name -> ... }
"writeBytes"      -> { uri, bytes -> ... }
"exists"          -> { uri -> ... }
```

参考实现：

```kotlin
private fun createDirectory(parentUri: Uri, name: String): String? {
    val parent = DocumentFile.fromTreeUri(this, parentUri) ?: return null
    return parent.createDirectory(name)?.uri?.toString()
}

private fun createFile(parentUri: Uri, mime: String, name: String): String? {
    val parent = DocumentFile.fromTreeUri(this, parentUri) ?: return null
    return parent.createFile(mime, name)?.uri?.toString()
}

private fun writeBytes(uri: Uri, bytes: ByteArray): Boolean = runCatching {
    contentResolver.openOutputStream(uri, "wt")?.use { it.write(bytes) }
    true
}.getOrDefault(false)
```

注意：

- `DocumentFile.createFile("image/jpeg", "page-0001")` 有的提供方会自动补 `.jpg`，有的不补；写入前用 `findFile` 兼容两种名字。
- 单次 `writeBytes` 控制在 32 MB 以内；成品图一般 < 5 MB。
- 用户选输出树后要 `takePersistableUriPermission(uri, READ|WRITE)`，否则重启后写不了。
- 不要申请 `MANAGE_EXTERNAL_STORAGE`。

Dart 侧：

```dart
final dirUri = await saf.createDirectory(treeUri, '译_${gallery.title}');
final fileUri = await saf.createFile(dirUri, 'image/jpeg', 'page-0001');
await saf.writeBytes(fileUri, jpegBytes);
```

## 8. 服务端当前限制（客户端要知道）

1. **渲染是“纯色/中位色块 + 文字”**，没有 MI-GAN 背景修复；复杂网点/渐变页会看到色块。后续可能加 `renderMode`，当前不要依赖。
2. **竖排文字**暂按横排渲染；日漫竖排气泡可能排版不自然。
3. **`source=auto` 会按每块文本猜语言**；纯汉字台词可能被猜成中文而不翻译。日文漫画请传 `source=ja`，保证纯汉字块也按日文处理。
4. **`render` 缓存只有 4 张/10 分钟**；必须收到响应后立刻下载。
5. **串行**：同时只能跑一个图片请求；同传/识图运行时也会 409。
6. **单边 4096 / 32 MiB**；更大的图请客户端先降采样。
7. **服务需要翻译 App 进程活着**；被系统杀后 health 连接拒绝，图集端要提供“打开同传互译”按钮。
8. **token 会变**；设置页“重新生成”后旧 token 立即 401。
9. **OCR 当前不支持韩文**：`ppocrv5_dict.txt` 只有 2 个 Hangul 字符（오/으），韩文会被识别成中文/符号乱码；`source=ko` 也不能让 OCR 认识韩文。韩文页需要单独的韩文 OCR 模型，或由电脑端 OCR 处理；客户端遇到韩文图集应提示“暂不支持韩文 OCR”，不要反复重试。
10. **单条翻译失败时字段是 `ok=false` + `error`**；但 `source=auto` 把某块猜成目标语言时，当前会返回 `ok=true` 且 `target=""`（源=目标跳过），客户端应把空 `target` 也当作“未翻译”，不要当成功。
11. **日文 OCR 的错字会直接导致空译文**：mobile OCR 可能把片假名 `カ` 认成汉字 `力`、把 `いいそう` 认成 `いいいそう`；这类错字送进 2B 会返回空。批量日漫建议切“高精度 server”OCR，或对 OCR 结果做常见片假名清洗。

## 11. 实现现状（图集端 1.3.0+6，2026-10-31）

本节记录**实际实现与本文件前文的差异**，以实现为准。前文是设计与验收依据，本节是现状说明。

### 11.1 流程差异

| 前文设计 | 实际实现 | 原因 |
| --- | --- | --- |
| 每次从菜单弹「配置对话框」 | 配置收进 **设置 → 翻译**（配对 / 存放位置 / 源语言 / 目标语言 / 测试连接），菜单只负责「开始翻译」 | 用户要求「连接过一次就不再重复手动连接」 |
| 菜单点开才校验配对 | 弹出「开始翻译」确认层（`lib/ui/translation_flow.dart`），层内显示配对状态、存放位置、语言与页数/耗时预估 | 一屏看清将发生什么 |
| 输出目录按批次新建（含时间戳） | 固定为 `用户选的树 / 原名<AITranslate>/`，重译复用同名目录 | 用户要求命名继承原名 + 断点续传 |
| 进度只看一个页面 | **底部导航条上方常驻细进度条** + 第 4 个 tab「翻译处理」看详情 | 用户要求后台进度条 |
| 无任务列表 | `TranslationTask` 持久化到 `SharedPreferences: translation.tasks.v1`（最多 100 条），重启后 `running` 一律视为 `stopped` | 进程被杀后能续跑 |
| 无单图入口 | 阅读器顶栏「翻译本页」按钮（不显示进度，4 分钟超时） | 用户 m02557 |

### 11.2 关键实现文件

- `lib/core/bridge/bridge_client.dart`：HTTP 客户端（health / text / image / render），`BridgeException` 带 `code` 与 `isRetryable`。
- `lib/core/bridge/bridge_config.dart`：配对串解析（JSON 或纯 token）、配置持久化（`bridge.config.v1`）、语言表。
- `lib/core/bridge/translation_job.dart`：串行逐页翻译，写 `manifest.json`，`translatedDirName()`、`pageFileName()`、GIF 直拷、`translateOne()`。
- `lib/core/bridge/translation_service.dart`：单例服务，`start/pause/stop/resume/forget/translatePage/probe`，`active` 与 `tasks` 两个 `ValueNotifier`。
- `lib/ui/translation_flow.dart`：开始确认层 + 出错排障文案 + 重复翻译提醒。
- `lib/ui/translation_page.dart`：「翻译处理」tab（任务卡片、进度、暂停/继续/终止、跳到译文）。
- `lib/ui/settings_page.dart`：翻译分区（配对、测试连接、存放位置、语言）。
- `lib/ui/gallery_list_page.dart`：菜单「翻译」、封面「已翻译」角标。
- `lib/ui/viewer_page.dart`：顶栏「翻译本页」。
- `android/.../MainActivity.kt`：SAF 写入通道（`pickOutputTree` / `createDirectory` / `createFile` / `writeBytes` / `writeFileAtomic` / `exists`）。

### 11.3 落盘与续跑细节

- 目录名：`TranslationJob.translatedDirName(title)` = 清洗后的标题 + 字面量 `<AITranslate>`（尖括号保留）。
- 页文件名：`page-%04d.jpg`（render=1）或 `page-%04d.gif`（动图原样复制，`copied:true`）。
- `manifest.json` 在输出目录内，`SafChannel.writeFileAtomic` 写（临时名 + rename）；语言不匹配的旧 manifest 直接丢弃。
- 续跑：`output` 已存在且 `error == null` 的页记为 `skipped`，不重复请求。
- 每页（以及续跑跳过判定）都会更新 manifest，所以任何时刻终止都能保留已完成的页。
- `render_gone`（410）会让该页重发一次；仍失败则该页保存原图并标 `renderMissing`。

### 11.4 与翻译 App 的联调事实（真机实测）

- health 不带 token；其余接口带 `X-Bridge-Token`。
- `PairActivity` 是 `exported="false"`，**只能用剪贴板配对**（同传互译 → 设置 → 图集互联 → 配对 → 复制）。
- 单通道：text 与 image 共用一个 busy 锁，冲突返回 `409 busy`（客户端退避重试）。
- token 48 位 hex；翻译 App 重装或清除数据后会变，需重新配对。
- 实测单页 900×1200、8 个文本框 ≈ 2.5 s；1440×3200 漫画页按 3~10 s/页估。

### 11.5 1.3.1 修的两个原生侧坑（都会让翻译第一页就失败）

1. **`isTreeUri` 误判子文档**：原实现直接用 `DocumentsContract.isTreeUri`，
   而它对树内子文档 URI（`…/tree/<id>/document/<id>/x.jpg`，首段同样是
   `tree`）也返回 true。于是 `sizeOf()` 开头的“树 URI 没有大小”把一张真实
   图片报成 0 字节，客户端按长度读就直接抛 `Bad state: 文件为空`。
   现在只认路径段正好两段（`tree` + documentId）的才是树 URI。
   同一个 bug 还会让 `listTree(子目录文档 URI)` 走 `fromTreeUri` 返回空列表，
   即翻译完成后 `importSingleFolder` 也会失败。
2. **输出目录只持久化了读权限**：`takeTreePermissionIfNeeded` 把
   `data.flags` 与掉了写标志，只持久化 `GRANT_READ`。结果是“选一次就记住”
   只在当前进程有效，重启后写产物抛 `SecurityException`。现在按提供方实际
   授予的标志持久化（读类选择器本来就只给读标志，行为不变）。

客户端的兜底：`readAllChunked()`（`lib/core/byte_source.dart`）改为**不看
`length()`**、按块读到 EOF，长度只用于判断是否超上限；`translation_job` 的
文件夹分支改用它，错误信息也带上了文件名。

### 11.6 1.3.2 阅读器单图翻译的显示与重试

- **就地替代**：`translatePage()` 成功后，阅读器从翻译图集里把刚写好的那页
  读回来就地显示（`Image.memory`），不占用按窗口管理的解码缓存。
- **持久**：译文的唯一数据源是磁盘上的翻译图集
  （`TranslationService.loadTranslatedPage()` 按 `page-%04d.jpg|gif` 查找，
  名字对不上时退回按页序取）。所以**退出重进后译文仍在**，而不是只活在
  内存里——这正是原来「退出后图片会消失」的原因。
- **看原图**：本页有译文时顶栏出现切换按钮（1.3.4 起改用
  `Icons.compare` / `Icons.compare_outlined`，见 §11.8；此前用
  `Icons.translate` ↔ `Icons.image`，会和右边「翻译这一张」撞成两个 文A），
  切回原图只影响显示，不改任何文件。
- **失败可重试**：发过去的永远是原图（job 按索引从原图集读字节），所以
  失败后可以反复点「翻译这一张」，不会拿上一版译文再翻一遍。
- **动图**：`page.copied == true` 时提示「这张是动图，已原样复制」，不做替换。

### 11.7 1.3.3 修 `MKFILE_FAILED`（`SingleDocumentFile` 不能建文件/枚举）

现象：翻译能跑，但每一页都失败，提示
`PlatformException(MKFILE_FAILED, 无法创建文件, null, null)`；
而且翻译图集始终不出现。

根因不是权限，而是 AndroidX `DocumentFile` 的两个实现各有残缺：

| 实现 | 拿到方式 | 能枚举子项 | 能在里面建文件 |
| --- | --- | --- | --- |
| `TreeDocumentFile` | `fromTreeUri(tree)` | ✅ | ✅ |
| `SingleDocumentFile` | `fromSingleUri(doc)` | ❌ `listFiles()` 抛 | ❌ `createFile()` 抛 |

翻译的产物目录是「树里的**子目录文档 URI**」（`createDirectory` 的返回值），
所有写入/列举都落在 `SingleDocumentFile` 上：`findFile()`/`createFile()`
抛 `UnsupportedOperationException()`（**没有 message**，所以错误串是
`无法创建文件 / null / null`），`listFiles()` 抛异常后被吞成空列表 →
`importSingleFolder` 拿到 0 张图 → 翻译图集永远不出现。

改法（`MainActivity.kt`）：

- 新增 `childrenOfDirectory(parent): List<ChildDoc>`：统一用
  `DocumentsContract.buildChildDocumentsUriUsingTree(treeUri, parentId)` +
  `COLUMN_{DOCUMENT_ID,DISPLAY_NAME,MIME_TYPE,SIZE,LAST_MODIFIED}` 查询，
  树 URI 与子目录文档 URI 都适用（子目录的 treeId 用
  `DocumentsContract.getTreeDocumentId(parent)` 反推）。
- `listTree(uri)` 改为它的投影，字段仍是 `uri/name/isDirectory/size/lastModified`。
- `createFile(parent, name, mime)`：树父 → `DocumentFile.fromTreeUri` 原路；
  子目录文档父 → 先 `childUrisOf(parent, name)` 删同名旧文件，再
  `DocumentsContract.createDocument(...)`，最后 `normalizeName()` 修掉
  提供方自动补的扩展名。
- `writeFileAtomic()` 也走 `createFile` 建 `.tmp`，再删旧文件后
  `renameDocument`；`createDirectory()` 明确只接受树 URI。
- `runOffMainThread` 的错误串改为 `e.message ?: "错误描述（异常类名）"`：
  以前 `UnsupportedOperationException` 这类无 message 的异常只回一句
  「无法创建文件」，把唯一的线索丢掉了。

教训：**SAF 写能力不能只看「权限有没有」，还要看 DocumentFile 是哪一种实现**；
“能创建目录”不等于“能在该目录里创建文件”。

### 11.8 1.3.4 去掉「翻译处理」标签页 + 译文叠放修正

需求原话（m03746）：「移除翻译处理的边栏，直接使得翻译后的和原图叠在一起，
用那个原图切换按钮切换」。

- **底部只剩三栏**（收藏夹 / 图集 / 设置）。`TranslationPage` 改为普通
  `MaterialPageRoute`，入口是底部导航上方的那条进度条；没有正在跑的任务但
  还留着历史记录时，那里显示一条 24dp 高的小入口「翻译处理记录」。
- **译文叠放原来根本没生效**：`_probeTranslated()` 的门槛写成了
  `gallery.isTranslated`（= `translatedFromId != null`，含义是「我本身是
  翻译产物」），所以**原图集**里永远不查译文。改为
  `Gallery.hasTranslation`（= `translatedToId != null`）。
- **封面「已翻译」角标也长错了位置**：同一个语义错误让角标出现在翻译图集
  身上，而点击处理读的又是 `translatedToId`（翻译图集该字段为 null），于是
  「点了跳不动」。同一处改用 `hasTranslation`。
- **两个 文A 撞脸**：切换按钮与「翻译这一张」都用 `Icons.translate`。
  切换改用 `Icons.compare`（译文态）/ `Icons.compare_outlined`（原图态）。
- **进度条不刷新**：`_onProgress` 是在同一个 `TranslationTask` 实例上改字段，
  裸 `ValueNotifier` 判定「值没变」不通知。新增 `ActiveTaskNotifier`
  （`publish()` 对同一实例也 `notifyListeners()`）。
- **行级失败要说清**：本机模型偶尔对某些句子返回空译文，服务端会把该行
  标成 `ok=false, error="模型返回空译文"`，**整页仍然成功**（实测：
  `stats{blocks:3,translated:2,failed:1}`）。阅读器提示改为
  「已翻译并存入翻译图集；其中 N 行没翻出来（模型返回空译文）」。

已知的服务端行为（不是本仓库的 bug，联调时别误判）：

- 同一句话走 `/v1/translate/text` 会稳定返回
  `HTTP 502 {"code":"translation_failed","message":"模型返回空译文"}`
  （例：`仕事が終わったら、駅の近くで待ち合わせてもいいですか。`，
  约 4.0 s）；拆成两半或换成同义句都能正常翻。文本接口把行级失败升级成
  502，图片接口则降级为 `lines[i].ok=false`，两者行为不一致。
- 因此**整页失败**只会在网络/鉴权/忙碌/写文件这些层面发生；单句翻不出来
  只会让那一行留原文。

## 12. 1.3.5 / 1.3.6：翻译目录的命名现实与去重

### 12.1 <AITranslate> 会被文件系统改名

图集端想要的目录名是 <原名><AITranslate>（字面尖括号）。内部存储（F2FS）
可以原样建出来，但**外置存储 / exFAT 上尖括号不合法**，DocumentsProvider 会
把它改写成 `_AITranslate_`，实测落在
`/storage/emulated/0/便携存储/APPdata/AndroidPicture/111_AITranslate_ (2)/`。

1.3.4 及以前的 `_resolveDir()` 只做字符串精确匹配，于是每次翻译都以为
目录不存在 → 再建一个 → SAF 自动加 ` (2) (3) …` 后缀 → 每个目录只装当次
那一页，列表里堆出一串 1 张的「重复翻译图集」。

1.3.5 的修法（`lib/core/bridge/translation_service.dart`）：

- `_normalizeDirName(name)`：去掉 `<>:"/\|?*` 与控制字符、去掉 `_` 与
  空白、转小写，用来做**宽松比对**；
- `_resolveDir()`：先精确匹配，再按归一化名匹配；命中多个候选时逐个
  `listTree` 数 `page-` 开头的文件，**选页数最多的那本复用**；
- 建目录后用 `_actualDirName()` 把提供方实际给的名字读回来存进任务，
  下次直接按 URI 复用，不再靠猜。

### 12.2 重复翻译图集自动收敛

1.3.6 在每次同步输出图集后调用 `_dropStaleTranslationGalleries()`：
把 `translatedFromId` 指向同一原图集、且标题归一化后相同的其它图集，
若页数不多于保留的那本，就 `GalleryRepository.removeFromIndex()`。

**只从索引里移除记录和封面缓存，不删除、不移动任何照片文件**——与
「严禁删除本地文件」的约束一致。真机实测：4 本收敛成 2 本（原图集 + 页数
最多的翻译图集）。

### 12.3 版本

- `1.3.5+11`：目录宽松匹配 + 同名多候选取页数最多者 + 回写真实目录名。
- `1.3.6+12`：重复翻译图集自动收敛。

## 13. 1.3.7 译文改为挂在原图集（不再建翻译图集）

### 13.1 为什么改

1.3.6 及以前把译文目录 `111<AITranslate>` 导入成一本**独立图集**（旧 JSON
里的 `trTo` / `trFrom` 双向关联）。这让列表里多出一本图集，更麻烦的是：
用户一旦把「翻译图集」移出列表，索引没了，译文就**再也看不到**——文件
还在盘上，软件却不认识它们了。

1.3.7 起译文属于**原图集**：每本原图集在 `TranslationSetStore` 里最多有
一条「翻译集」，记录译文目录与「第几页 → 哪个文件」，不再产生图集。

### 13.2 数据结构

`lib/core/bridge/translation_set.dart`，SharedPreferences 键
`translation.sets.v1`，值是 `{galleryId: setJson}`：

```json
{
  "galleryId": "…",
  "dirUri": "content://…/tree/…",
  "dirName": "111_AITranslate_",
  "source": "ja",
  "target": "zh",
  "updatedAtMs": 1700000000000,
  "pages": [
    {"index": 2, "file": "page-0003.jpg",
     "uri": "content://…/document/…", "copied": false,
     "translated": 7, "failed": 1}
  ]
}
```

- `index` 是原图集里的页序（0 基），由成品文件名 `page-0003.jpg` 反推；
- `uri` 是 `SafChannel.createFile()` 返回的文件 URI，阅读器直接用它读
  译文，**不再按目录名重扫**；
- `copied: true` 表示动图原样复制（不是译文），阅读器照样叠上去；
- 所有 `fromJson` 都容错：缺字段/类型错取默认值，没有 `uri` 的页不登记。

`Gallery` 新增 `translatedPages`（JSON 键 `trPages`），`hasTranslation`
改为 `translatedPages > 0`。旧的 `translatedToId` / `translatedFromId`
字段保留（读得懂旧 JSON、供一次性迁移），新代码不再写入。

### 13.3 写入路径

`TranslationJob` 在 `SafChannel.createFile()` 成功后把 `fileUri` 填进
`TranslationPageResult.uri`（动图复制与正常译文两处）。`_onPageDone()`
收到一页就 `TranslationSetStore.recordPage()` 登记，并
`GalleryRepository.setTranslatedPages()` 更新页数（只在变化时写盘）。

**不再每页重扫翻译目录**：1.3.6 的 8 秒节流本质是为了 `importSingleFolder`
/ `updateGallery`，现在 URI 跟着结果直接回来，扫目录这一步整个删掉了。
任务结束时也不再同步索引。

### 13.4 阅读

- `TranslationService.loadTranslatedPage(gallery, index)` 查
  `pageOf(galleryId, index)`，`SafChannel.sizeOf(uri)` 拿长度后
  `GalleryRepository.byteSourceFor(uri, knownLength: …)` +
  `readAllChunked()`；任何异常都返回 `null`（阅读优先，不打断）。
- 阅读器顶栏的 compare 按钮行为不变：本页有译文时出现，切换原图/译文。
- `ViewerPage` 新增 `initialIndex` / `startTranslated`：列表「已翻译」角标、
  翻译任务卡「查看译文」都跳到**原图集**第一页有译文的页，并先显示译文。

### 13.5 旧数据迁移

`TranslationService.load()` 末尾调用一次 `initSets()`（幂等）：

1. 等仓库索引就绪（`isLoaded`）再遍历图集；
2. 若 `g.translatedToId != null` 且旧的翻译图集 `t` 还在索引里：
   `t.sourcePath` 当 `dirUri`、`t.title` 当 `dirName`，把 `t.images` 里
   文件名匹配 `page-(\d+)\.(jpg|png|gif)` 的条目转成
   `TranslationPageEntry(index = n-1, uri = img.path, copied = .gif)`，
   `adopt` 成 `g` 的翻译集；
3. `setTranslatedPages(g, pages.length)`、清空 `g.translatedToId`，
   再 `removeFromIndex(t)`——**只摘索引与封面缓存，不删除、不移动任何文件**；
4. 若旧翻译图集里一个 `page-` 文件都认不出，就**不摘它的索引**：否则
   这些文件会在软件里彻底消失，保留成一本普通图集反而更安全；
5. 没人认领的旧翻译图集（原图集已不在列表）也一并摘掉索引。

### 13.6 清除翻译关联

图集三点菜单新增「清除翻译关联」：`TranslationSetStore.remove(id)` +
`setTranslatedPages(g, 0)`。**只清索引，不删任何文件**；译文目录原地
保留，以后重新翻译会在同一目录里续写。菜单里「从列表移除」的说明也补了
一句「翻译结果不受影响」。

### 13.7 版本

- `1.3.7+13`：译文按页挂在原图集上；迁移旧翻译图集；角标/任务卡改跳原图集；
  清除翻译关联只清索引。
